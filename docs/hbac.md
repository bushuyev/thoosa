# HBAC workflow

The HBAC sample project uses EEG data from the [HMS – Harmful Brain Activity Classification competition on Kaggle](https://www.kaggle.com/competitions/hms-harmful-brain-activity-classification/data). It demonstrates a multi-stage time-series classification pipeline, from discovering recurring signal patterns to training a final classifier.

[`run_all`](../crates/thoosa_projects/thoosa_hbac/src/run_all.rs) coordinates the following steps:

1. **Find and select motifs.** [`FindMotifsStage`](../crates/thoosa_motifs/src/stages/find_motifs.rs) compares EEG time-series windows using Euclidean distance to discover recurring patterns, or motifs. [`SelectMotifsStage`](../crates/thoosa_motifs/src/stages/select_motifs.rs) evaluates the candidates against configured quality criteria and retains suitable motifs.
2. **Train motif networks.** [`TrainMotifNets`](../crates/thoosa_motifs/src/stages/train_motif_nets.rs) trains a separate small neural network for each selected motif. These networks learn to recognize their corresponding patterns in EEG windows.
3. **Train label networks.** [`TrainLabelNets`](../crates/thoosa_motifs/src/stages/train_label_nets.rs) trains label-specific neural networks using the motif networks' outputs as features, connecting detected patterns to brain-activity labels.
4. **Train the final classifier.** [`TrainFinalNet`](../crates/thoosa_motifs/src/stages/train_final_net.rs) learns to combine the label networks' outputs into the final classification predictions.

The workflow passes saved run-configuration IDs between stages so downstream training uses the preceding stages' results. It supports grid search and [parameter optimization](opt.md), with optional plots for inspecting selected motifs.

Exploratory runs with a few hours of training have produced modest classification accuracy, above random guessing. The project's primary goal is to demonstrate a pipeline with varied computational tasks—signal comparison, motif selection, and several levels of neural-network training—using Thoosa's asynchronous execution and memory-pressure handling, rather than to provide a competitive classification model.

For command examples covering data import, plotting, individual stages, and the complete `run-all` workflow, see the [HBAC command cheat sheet](../crates/thoosa_projects/thoosa_hbac/commands.txt). Run Cargo commands from the repository's `crates/` directory and adapt workspace paths, resource groups, and run-configuration IDs to your data.

The default `run_all_config_0` profile is an experimental accuracy-oriented starting point for 200 Hz EEG. It has not been benchmarked on the real dataset:

- Discovery uses 16 configurations: four window sizes (40, 80, 120, 160 filtered samples), two median widths (5, 101), and two Savitzky–Golay filters (window/order/stride: 9/2/2 and 193/1/10). FFT notch filters first remove 0–0.5 Hz and 30–100 Hz. The resulting motif durations span 0.4–1.6 seconds in the lightly smoothed branch and 2–8 seconds in the heavily smoothed branch. The latter retains the scale of the earlier useful motif-screening configuration. Replicate padding avoids zero-padding edges.
- Shape-normalized Euclidean distance and an accumulated 0.1-quantile distance cutoff replace raw-distance matching with `q=5.0` (which was clamped to the maximum distance). At least ten occurrences are required. Selection checks thickness, inlier ratio, and consensus variation; it permits periodic signals instead of applying the previous anti-periodicity score. These thresholds are hypotheses for the next real-data run.
- Cosine detectors get up to 60 epochs, normalized prototype initialization, and a negative initial bias. Label models use smaller attention embeddings with more dropout. The final classifier searches shallow networks with hidden width 1–16 times the number of label models, replacing the previous multiplier up to 8000. Motif detectors use batches of 32; label and final models use batches of 10 to remain compatible with small resource groups. Each stage retains its best validation checkpoint. Trial budgets remain 30 per motif, 100 per label, and 100 for the final model.
- `run-all --motif-slices-step` now defaults to 5 filtered samples and is used for both label and final training. An explicit command-line value still overrides it. Dense scans increase feature-generation cost, particularly on long recordings.

For comparison runs, hold the imported data, resource groups, scan step, and motif limits fixed. Keep patients in separate training and validation groups, and keep discovery/selection resources inside training. Use a separate untouched patient holdout to evaluate the selected final model: the validation group is reused to choose models at several stages. Train all six label models and include mixed-vote examples when evaluating the final classifier. Its soft-target cross-entropy differs from the competition's [KL-divergence metric](https://www.kaggle.com/competitions/hms-harmful-brain-activity-classification/overview/citation) by target entropy, so lower loss ranks predictions equivalently on the same fixed examples; the numeric loss is not the Kaggle score.

A remaining data limitation is outside this configuration: the current importer loads each whole EEG parquet and takes the first vote vector for its `eeg_id`. It does not align each annotation with its labeled central ten-second interval. Existing resource groups also do not establish patient separation automatically. Filter and model tuning cannot correct these issues; they must be accounted for when interpreting real-data results. This profile assumes the workspace still contains 200 Hz data; pre-decimated imports require different filter frequencies and window sizes.
